Guía funcional

Cómo funcionan las conversaciones

Del correo que llega de un cliente hasta que se responde y se le hace seguimiento. Todo el recorrido, explicado de forma simple.

01 Las piezas del sistema

Los elementos básicos con los que se trabaja a diario.

Casilla
El buzón de correo de un hotel. Cada hotel tiene la suya.
Conversación
Todo el ida y vuelta con un mismo cliente sobre un mismo tema, agrupado en un hilo.
Mensaje
Cada correo individual, del cliente o nuestro, dentro de la conversación.
Estado
La columna del tablero donde vive la conversación según el punto de gestión en que está.
Respuesta modelo
Un texto de respuesta ya redactado para situaciones frecuentes, listo para reutilizar. También llamado template.

02 El tablero de estados

Cada conversación avanza por estas columnas.

Nuevo

Llegó un correo y aún no fue procesado.

Pendiente de revisión

Necesita que alguien lo mire antes de responder.

Respuesta preparada

Hay una respuesta sugerida lista para revisar y enviar.

Esperando cliente

Respondimos y aguardamos que el cliente conteste.

Requiere atención

Un caso especial que necesita gestión manual.

Cerrado

La conversación terminó o se resolvió.

03 Cuando llega un correo

Cómo se crea y organiza una conversación, de forma automática.

Se detecta el correo al instante

Apenas un cliente escribe, el sistema recibe el aviso y empieza a trabajar sin que nadie tenga que intervenir.

Se agrupa en la conversación correcta

Si pertenece a un intercambio existente, se suma a ese hilo. Si es un tema nuevo, se crea una conversación nueva. Los mensajes repetidos se ignoran.

Se marca como pendiente

Queda señalada como no leída y ubicada en la columna de entrada, para que el equipo sepa que hay algo por atender.

Se analiza y se prepara una respuesta

De forma automática se lee el mensaje, se clasifica en la columna que corresponde y se deja lista una respuesta sugerida según el estilo del hotel y casos anteriores parecidos.

Resultado: sin intervención manual, la conversación queda creada, ordenada en el tablero y con una respuesta propuesta para revisar.

04 La respuesta sugerida

El asistente prepara, pero nunca envía por su cuenta.

Qué hace el asistente

  • Entiende de qué trata el correo del cliente.
  • Elige la columna del tablero más adecuada.
  • Busca respuestas modelo que apliquen al caso.
  • Se apoya en conversaciones anteriores parecidas.
  • Redacta una respuesta en el idioma y tono del hotel.

Qué queda en tus manos

  • Revisar la respuesta propuesta.
  • Editarla o reescribirla si hace falta.
  • Decidir el momento del envío.
  • Cambiar la conversación de columna.
  • Asignarla a un responsable del equipo.

El asistente nunca envía correos solo. Siempre deja la propuesta lista y una persona tiene la última palabra.

05 Las respuestas modelo

Textos ya redactados para las consultas más frecuentes de cada hotel.

Cada hotel arma su propia biblioteca de respuestas modelo para los temas que se repiten (disponibilidad, tarifas, horarios de check-in, servicios, etc.). Así las contestaciones son consistentes y rápidas.

Nombre
Cómo se identifica la respuesta modelo dentro de la biblioteca.
Cuándo usarla
Una breve descripción del tipo de consulta para la que sirve.
Texto
El contenido de la respuesta que se reutiliza.
Etiquetas
Palabras clave que ayudan a encontrarla y a relacionarla con cada consulta.

Cómo se usan dentro del flujo

Se busca la respuesta modelo adecuada

Cuando llega un correo, el asistente revisa la biblioteca del hotel y busca las respuestas modelo que mejor coinciden con la consulta.

Si una aplica, la usa como base

Toma la respuesta modelo más adecuada y la adapta al correo puntual del cliente para armar la propuesta.

Si ninguna aplica, redacta desde cero

Cuando no hay una respuesta modelo que encaje, el asistente escribe una respuesta nueva apoyándose en el tono del hotel y en conversaciones anteriores parecidas.

El equipo mantiene esta biblioteca: puede crear, editar, activar o desactivar respuestas modelo en cualquier momento. Cuantas mejores sean, más precisas y rápidas serán las propuestas del asistente.

06 Qué puede hacer el equipo

Las acciones disponibles sobre cada conversación.

Marcar leída / no leída
Mover de columna
Asignar a un responsable
Responder al cliente
Pedir una nueva sugerencia
Buscar y filtrar

Al responder: el correo sale al cliente, la respuesta queda guardada en el hilo, la conversación se marca como leída y pasa a “Esperando cliente”.

07 Seguimiento automático

El sistema vigila las conversaciones para que ninguna quede olvidada.

Cada tanto revisa las conversaciones donde ya respondimos y el cliente no volvió a escribir, y actúa según el tiempo transcurrido:

Pasan 5 días

Si el cliente sigue sin responder, la conversación se mueve a “Requiere atención” para que el equipo la gestione manualmente.

Siempre

Cada cambio automático queda registrado en el historial de la conversación.

Si el cliente vuelve a escribir, la conversación se reactiva: vuelve a marcarse como pendiente, sube en el tablero y se prepara una nueva respuesta. El ciclo empieza otra vez.

08 El recorrido completo

Todo el ciclo de una conversación, de principio a fin.

Llega el correo del cliente

Se crea o actualiza la conversación y se marca como pendiente.

Se prepara la respuesta

Se clasifica la conversación y queda una propuesta lista para revisar.

El equipo revisa y responde

Se ajusta lo necesario y se envía la respuesta al cliente.

Se espera al cliente

La conversación queda a la espera de la próxima respuesta.

Seguimiento

Si el cliente no vuelve en 5 días, la conversación pasa a “Requiere atención” para gestión manual. Si responde, el ciclo vuelve a comenzar.
